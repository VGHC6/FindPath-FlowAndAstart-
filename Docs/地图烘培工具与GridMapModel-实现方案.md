# 地图烘培工具 + GridMapModel —— 实现方案

> 状态：方案已定，代码待落盘
> 本文档放在 `Docs/`（`Assets/` 之外），避免 Unity 把它导入资源库、生成 .meta、打进包体。
> 前置文档：`Docs/地图烘培与格子碰撞-开发思路.md`（总体架构与待定决策）

---

## 一、目标

把 3D 场景（地面 + 障碍物）烘培成一张格子表，存成 Unity 资产；运行时把资产灌进 `GridMapModel` 的一张 `Dictionary<int, BaseNode>` 里，敌人占据的格子由运行时动态改写 —— 这就是格子预约式碰撞的数据底座。

本次范围：**烘培工具 + GridMapModel + 资产**。敌人移动系统（两阶段移动、抢占裁决）见前置文档 Phase 4，不在本次范围内。

---

## 二、已确认的决策

| 项 | 决策 | 理由 |
|---|---|---|
| 数据存放方式 | **ScriptableObject 资产**（不是生成成 C# 代码） | 重烘不触发重编译；Inspector 可看；diff 可读 |
| 代码生成的作用 | **只产出类型骨架**，不含任何地图数据 | 数据在资产里，代码文件稳定不变 → 幂等 |
| 表结构 | **一张表**：`Dictionary<int, BaseNode>` | 与 `FlowFieldUtil.cs:65` 的 `nodes` 同构；`isWalkable` 与 `occupant` 同格并存 |
| 静态数据来源 | 烘培期写资产，运行时 `Apply()` 时**拷值**进表 | 绝不持资产数组的引用，避免误写落盘 |
| 动态数据归属 | `occupant` 字段，**Model 自己置 0** | 与资产结构上无关，运行时随便改 |
| 表操作的封装 | Model 提供 `TryClaim / Release / IsBlocked` | 前置文档 Phase 3：Model 只管原子操作，裁决策略归 System |
| 索引公式 | `x * ySize + y`，全项目唯一一份 | 与 `FlowFieldUtil.cs:84` 的 `i * _ySize + j` 一致 |

### 「注入」这个词的两段含义

容易混淆，明确一下：

```
Editor 点「烘焙」  →  写 .asset 文件        ← 跨 domain，工具只能做这一件事
游戏启动 Apply()   →  把资产拷进 Model 的表  ← 这才是真的"注入进表里"
```

Editor 和 Play 是两套东西，**工具不可能直接把节点塞进运行时的对象**。想让"工具直接决定表内容"只有把数据生成为 C# 字面量一条路，代价是每次重烘全量重编译。所以选了资产。

## 三、分层落位

```
[Editor]     BakeMapCreate (EditorWindow)         ← 不在架构里，Editor/ 目录
                 │ 写出
[Data]       GridMapAsset : ScriptableObject      ← 静态只读资产（xSize/ySize/cellSize/origin/walkable）
                 │ 运行时读取
[Model]      GridMapModel : IGridMapModel         ← ★ 一张表：isWalkable（只读）+ occupant（可写）
                 │
[System]     （未来的 IAgentMoveSystem）           ← 两阶段移动、抢占裁决
                 │
[Controller] GridMapController (MonoBehaviour)     ← 把资产交给 Model
```

## 四、表结构

```csharp
public class BaseNode
{
    public int x;
    public int y;
    public bool isWalkable;   // 烘培期定死，运行时只读
    public int occupant;      // 0 = 空，>0 = 单位 ID，运行时唯一会变的字段
}
```

**三条读写纪律：**

1. **`isWalkable` 运行时只读。** 技术上改得到（`BaseNode` 是自己 `new` 的对象），但它是烘培产物，改了就和资产对不上。
2. **`occupant` 用 `int` 不用 `bool`。** 前置文档 Phase 3 的决策：必须知道"是谁占的"，否则释放和裁决都做不了。
3. **调用方不直接摸 `nodes`。** 走 `TryClaim / Release / IsBlocked` —— 以后加 Gizmos 可视化（Phase 6）或日志，改这三个方法就够了。

查询语义：`IsBlocked(x, y) = !isWalkable || occupant != 0`，即**静态 ∪ 动态**。

## 五、代码

### 5.1 `Assets/Scripts/Data/GridMapAsset.cs`

```csharp
using UnityEngine;

[CreateAssetMenu(fileName = "GridMap", menuName = "地图/格子地图资产")]
public class GridMapAsset : ScriptableObject
{
    public int xSize;
    public int ySize;
    public float cellSize = 1f;
    public Vector2 origin;
    public bool[] walkable;

    // 排错用，每次烘培覆盖
    public string bakedFrom;
    public string bakedAt;

    // ★ 全项目唯一一份索引公式（FlowFieldUtil.cs:84 用的是同一个）
    public static int Index(int x, int y, int ySize) => x * ySize + y;
    public int Index(int x, int y) => Index(x, y, ySize);

    public bool InBounds(int x, int y) => x >= 0 && x < xSize && y >= 0 && y < ySize;
    public bool IsWalkable(int x, int y) => InBounds(x, y) && walkable[Index(x, y)];

    public bool WorldToGrid(Vector3 worldPos, out int x, out int y)
    {
        x = Mathf.FloorToInt((worldPos.x - origin.x) / cellSize);
        y = Mathf.FloorToInt((worldPos.z - origin.y) / cellSize);
        return InBounds(x, y);
    }
}
```

`origin / cellSize / xSize / ySize` 必须和 `walkable` 一起存进资产 —— 这是「我明明烘过了为什么格子还是歪的」唯一的来源（前置文档 Phase 1）。

### 5.2 `Assets/Editor/MapBaker/Templates/GridMapModel.template.txt`

⚠️ **后缀必须是 `.txt`。** 放 `Assets/` 下的 `.cs` 会被 Unity 编译，模板会直接报一堆错。

```csharp
// <auto-generated> 由「地图烘焙」工具生成，请勿手改 </auto-generated>
using System.Collections.Generic;

public class BaseNode
{
    public int x;
    public int y;
    public bool isWalkable;   // 烘培期定死，运行时只读
    public int occupant;      // 敌人占格：0 = 空，>0 = 单位 ID，运行时唯一会变的字段
}

public interface IGridMapModel : IModel
{
    void Apply(GridMapAsset asset);
    BaseNode GetNode(int x, int y);
    bool IsBlocked(int x, int y);
    bool TryClaim(int x, int y, int id);
    void Release(int x, int y, int id);
    int XSize { get; }
    int YSize { get; }
}

public class GridMapModel : IGridMapModel
{
    // 就是这张表，对标 FlowFieldUtil.cs:65
    private readonly Dictionary<int, BaseNode> nodes = new Dictionary<int, BaseNode>();
    private GridMapAsset _asset;

    public int XSize => _asset != null ? _asset.xSize : 0;
    public int YSize => _asset != null ? _asset.ySize : 0;

    public IAchitecture GetArchitecture() => mobaTest.Interface;
    public void SetArchitecture(IAchitecture architecture) { }

    public void Init() { }   // 资产还没喂进来，这里建不了表

    public void Apply(GridMapAsset asset)
    {
        _asset = asset;
        nodes.Clear();
        for (int x = 0; x < asset.xSize; x++)
        {
            for (int y = 0; y < asset.ySize; y++)
            {
                int idx = asset.Index(x, y);
                nodes[idx] = new BaseNode
                {
                    x = x,
                    y = y,
                    isWalkable = asset.walkable[idx],   // 拷值，存的是新对象
                    occupant = 0,
                };
            }
        }
    }

    public BaseNode GetNode(int x, int y)
    {
        if (_asset == null || !_asset.InBounds(x, y)) return null;
        return nodes[_asset.Index(x, y)];
    }

    public bool IsBlocked(int x, int y)
    {
        var node = GetNode(x, y);
        if (node == null) return true;                    // 越界一律当阻塞
        return !node.isWalkable || node.occupant != 0;    // 静态 ∪ 动态
    }

    public bool TryClaim(int x, int y, int id)
    {
        var node = GetNode(x, y);
        if (node == null || !node.isWalkable || node.occupant != 0) return false;
        node.occupant = id;
        return true;
    }

    public void Release(int x, int y, int id)
    {
        var node = GetNode(x, y);
        if (node != null && node.occupant == id) node.occupant = 0;
    }
}
```

接口名用 `IGridMapModel` 而不是 `IBakeMap` —— `IBakeMap` 容易和"烘培这个动作"混。项目里每个 Model 都是「接口 + 实现」成对，注册时泛型参数填接口（见 `mobaTest.cs:13`、`PalyerModel.cs:12`）。写成 `IGridMapModel : IModel` + `GetArchitecture() => mobaTest.Interface` 是照 `PalyerModel.cs:35-41` 的项目惯例，不要用 `AbstractModel`（现有 Model 都没用）。

### 5.3 `Assets/Editor/BakeMap.cs`

```csharp
using System.Collections.Generic;
using System.IO;
using System.Linq;
using System.Text;
using UnityEditor;
using UnityEngine;

//生成地图Model文件
public class BakeMapCreate : EditorWindow
{
    private static BakeMapCreate _window;

    [SerializeField] private GameObject _mapPrefab;
    [SerializeField] private float _cellSize = 1f;
    [SerializeField] private LayerMask _obstacleMask;    // ★ 只勾障碍物层，别勾地面
    [SerializeField] private float _probeHeight = 0.5f;  // 探测高度：地面之上、障碍物高度之内

    private List<GameObject> _perfabChilds = new List<GameObject>();

    //地图需要的属性
    private Vector2 _origin = Vector2.zero;
    private int _xSize = 0;
    private int _ySize = 0;

    private const string ModelDir     = "Assets/Scripts/Model";
    private const string ModelPath    = "Assets/Scripts/Model/GridMapModel.cs";
    private const string TemplatePath = "Assets/Editor/MapBaker/Templates/GridMapModel.template.txt";
    private const string AssetDir     = "Assets/Resource/GridMaps";

    [MenuItem("Tools/地图烘焙")]
    public static void AssetBakeMapCreate()
    {
        _window = GetWindow<BakeMapCreate>(false, "地图烘焙", false);
        _window.Show();
    }

    private void OnGUI()
    {
        GUILayout.Label("地图烘焙工具");
        _mapPrefab = EditorGUILayout.ObjectField(_mapPrefab, typeof(GameObject), true) as GameObject;
        _cellSize = EditorGUILayout.FloatField("网格大小", _cellSize);
        _obstacleMask = EditorGUILayout.LayerMaskField("障碍物层", _obstacleMask);
        _probeHeight = EditorGUILayout.FloatField("探测高度", _probeHeight);

        if (GUILayout.Button("烘焙地图"))
        {
            GetMapSize();
            if (_xSize <= 0 || _ySize <= 0) return;

            BakeMap();             // ① 先写数据：不受重编译影响
            GenerateModelFile();   // ② 后生成代码：可能触发域重载，放最后
        }

        if (_xSize > 0 && _ySize > 0)
            EditorGUILayout.LabelField($"上次尺寸：{_xSize} x {_ySize}，原点：{_origin}");
    }

    private void GetMapSize()
    {
        if (_mapPrefab == null)
        {
            Debug.LogError("请先选择地图预制体");
            return;
        }

        _perfabChilds = _mapPrefab.GetComponentsInChildren<Transform>().Select(t => t.gameObject).ToList();

        // ★ 所有元素的合并包围盒（原版取的是"最大的单个元素"，多块拼的地图会算错）
        bool hasBounds = false;
        Bounds maxBounds = new Bounds();
        foreach (var item in _perfabChilds)
        {
            if (!item.TryGetComponent(out Renderer renderer)) continue;
            if (!renderer.enabled) continue;

            if (!hasBounds) { maxBounds = renderer.bounds; hasBounds = true; }
            else            { maxBounds.Encapsulate(renderer.bounds); }
        }

        if (!hasBounds)
        {
            Debug.LogError("地图预制体下没有任何带 Renderer 的元素");
            _xSize = _ySize = 0;
            return;
        }

        _xSize  = Mathf.CeilToInt(maxBounds.size.x / _cellSize);
        _ySize  = Mathf.CeilToInt(maxBounds.size.z / _cellSize);
        _origin = new Vector2(maxBounds.min.x, maxBounds.min.z);
        Debug.Log($"地图大小：{_xSize}x{_ySize},原点：{_origin}");
    }

    // ---------- 生成 Model 代码骨架 ----------

    private static void GenerateModelFile()
    {
        if (!File.Exists(TemplatePath))
        {
            Debug.LogError($"模板不存在：{TemplatePath}");
            return;
        }

        string content = File.ReadAllText(TemplatePath, Encoding.UTF8);
        content = content.Replace("\r\n", "\n").Replace("\n", "\r\n");   // 统一 CRLF，跟项目其它 .cs 一致

        // 幂等：内容没变就不写，省掉一次域重载
        if (File.Exists(ModelPath) && File.ReadAllText(ModelPath, Encoding.UTF8) == content)
        {
            Debug.Log("GridMapModel.cs 无变化，跳过生成");
            return;
        }

        Directory.CreateDirectory(ModelDir);
        File.WriteAllText(ModelPath, content, new UTF8Encoding(false));   // UTF-8 无 BOM
        AssetDatabase.Refresh();
        Debug.Log($"已生成：{ModelPath}");
    }

    // ---------- 烘焙：逐格探测障碍，产出资产 ----------

    private void BakeMap()
    {
        int total = _xSize * _ySize;
        var walkable = new bool[total];
        for (int i = 0; i < total; i++) walkable[i] = true;

        int blocked = 0;
        var half = new Vector3(_cellSize * 0.45f, _probeHeight * 0.5f, _cellSize * 0.45f);

        for (int x = 0; x < _xSize; x++)
        {
            for (int y = 0; y < _ySize; y++)
            {
                var center = new Vector3(
                    _origin.x + (x + 0.5f) * _cellSize,
                    _probeHeight,
                    _origin.y + (y + 0.5f) * _cellSize);

                // 靠 LayerMask 显式指定障碍物，不用 GetComponent<Collider>() 随便挑
                if (!Physics.CheckBox(center, half, Quaternion.identity, _obstacleMask)) continue;

                walkable[GridMapAsset.Index(x, y, _ySize)] = false;   // ★ 与 asset.Index 同一公式
                blocked++;
            }
        }

        WriteAsset(walkable);
        Debug.Log($"烘焙完成：{_xSize}x{_ySize}，障碍 {blocked} 格，可行走 {total - blocked} 格");
    }

    private void WriteAsset(bool[] walkable)
    {
        Directory.CreateDirectory(AssetDir);
        string path = $"{AssetDir}/{_mapPrefab.name}_GridMap.asset";

        // ★ 已存在就复用同一个实例，保住 guid —— 否则场景里拖的引用会断
        var asset = AssetDatabase.LoadAssetAtPath<GridMapAsset>(path);
        bool isNew = asset == null;
        if (isNew) asset = ScriptableObject.CreateInstance<GridMapAsset>();

        asset.xSize     = _xSize;
        asset.ySize     = _ySize;
        asset.cellSize  = _cellSize;
        asset.origin    = _origin;
        asset.walkable  = walkable;
        asset.bakedFrom = _mapPrefab.name;
        asset.bakedAt   = System.DateTime.Now.ToString("yyyy-MM-dd HH:mm:ss");

        if (isNew) AssetDatabase.CreateAsset(asset, path);
        else       EditorUtility.SetDirty(asset);

        AssetDatabase.SaveAssets();
        Selection.activeObject = asset;   // 顺手选中，方便立刻在 Inspector 里核对
        Debug.Log($"资产已写出：{path}（{(isNew ? "新建" : "覆盖")}）");
    }
}
```

### 5.6 占格调用点

前置文档 Phase 4 的两阶段移动还没做，但**表的读写纪律**现在就该定下来。

```csharp
// 在敌人 Controller 或未来的 IAgentMoveSystem 里
void MoveToNextCell(int x, int y)
{
    if (!_map.TryClaim(x, y, _unitId)) return;   // 被占了就这帧不动，等下次重试

    _map.Release(_oldX, _oldY, _unitId);         // ★ 先申请成功，再释放旧格
    _oldX = x; _oldY = y;
}

void OnDestroy()
{
    _map?.Release(_oldX, _oldY, _unitId);        // ★ 死了不释放 → 幽灵格占满地图
}
```

顺序不能反：先 `Release` 再 `TryClaim`，敌人自己卡在原地时会把自己的目标格判成阻塞。

## 六、坑清单

| 坑 | 说明 |
|---|---|
| **guid 会被改写** | 必须用 `LoadAssetAtPath` 复用实例。写成 `File.Delete` + `CreateAsset`，每次重烘 guid 都变，场景里拖的引用全断 |
| **模板后缀** | 模板必须是 `.txt`，放 `Assets/` 下的 `.cs` 会被 Unity 编译 |
| **行尾 / 编码** | 项目现有 .cs 是 UTF-8 无 BOM + CRLF，工具已按此对齐 |
| **时间戳不能进模板** | 每写一次都变，`if (内容相同) return` 的幂等永远失效，每次点按钮都重编译。所以放进了资产 |
| **`Assets/Resource` 是单数** | `Resources.Load` 只认 `Resources`。走 SerializeField 拖拽没事；想用 Resources.Load 得改名 |
| **先 Bake 再 Generate** | `AssetDatabase.Refresh()` 会触发域重载并打断当前调用栈。写资产不受影响，生成代码放最后 |
| **`GetMapSize()` 原实现是错的** | `BakeMap.cs:92-93` 取的是"最大的单个元素"而非所有元素的合并包围盒，且条件用了 `&&`。单块地面碰巧对，多块拼接或障碍物比地面大时 `_xSize/_ySize/_origin` 全错 → 整个格子系统跟着歪。改成 `Encapsulate` |
| **LayerMask 必须排除地面** | 否则 `Physics.CheckBox` 把地面自己判成障碍，整张图全不可走 |
| **`_probeHeight` 选值** | 要落在「地面之上、障碍物高度之内」，默认 0.5，按障碍物实际高度调 |
| **`Release` 要校验 id** | 没有 `node.occupant == id` 就是"A 死了却释放了 B 的格"，表会慢慢烂掉 |
| **`Release` / `TryClaim` 顺序** | 先释放再申请 → 自己卡住时把目标格判成阻塞 |

## 八、与 FlowFieldUtil 的关系（待迁移）

MapModel 建起来之后，`FlowFieldUtil.cs:70-105` 的 `Init(GameObject, float)` + `AddObstacle` 就是**重复劳动**了 —— 同一个 `origin / _xSize / _ySize` 被算两遍（`FlowFieldUtil.cs:74-77` vs 工具的 `GetMapSize`），早晚不一致，症状同样是"明明烘过了格子还是歪的"。

按前置文档 Phase 2：

- `FlowFieldUtil` 改成 `Init(GridMapAsset)`，**和 GridMapModel 读同一个资产**
- 删掉 `AddObstacle`（`FlowFieldUtil.cs:86`）和 `WorldToGridRange`（`FlowFieldUtil.cs:233`、`:256-268`）—— 烘培时已做完，运行时不再需要
- 保留 `IsWalkable` / `WorldToGrid` / `GridToWorld` / `GetDirection`

思路：**资产是唯一数据源，任何地方都不该再自己算一遍尺寸。** 两张表（GridMapModel 的地表 / FlowFieldUtil 的流场表）各自持有，但几何参数来自同一处。

本次不做，但写 MapModel 时心里要有数。

以下两项没定，会影响 `occupant` 的后续用法（来自前置文档第三节）：

- **② 玩家算不算格子？** 决定 `occupant` 是否要记录玩家占格、以及玩家是否走物理移动
